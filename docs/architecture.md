# 架构与数据操作

0.11.7 在既有 Compose / Java 结构上逐步拆分，保留原业务规则和数据库版本。不要为新增界面另建计时、额度或课程状态源。

## 当前边界

| 模块 | 职责 |
| --- | --- |
| Store | SQLite 数据、备份校验与恢复事务；原有数据库与备份版本 4 |
| Engine / Rules | 任务周期、实际计时、定位有效窗口与限制判定 |
| Scheduler / Reminders / AndroidCompat | 提醒调度、权限撤销回退与系统服务适配 |
| StatisticsRepository | 在 Store 锁内一次读取报告所需记录，转换为不可变输入快照 |
| StatisticsReport | 无界面、数据库与服务依赖的纯报告计算；单元测试可直接覆盖 |
| TimetableCsv | 无存储依赖的 CSV 解析、周次校验及导入冲突判定 |
| Timetable | 将解析结果映射到现有课表状态，维护既有周次和编辑规则 |
| DocumentTransfers | 有界文件读取及 UTF-8 写入，调用方必须放到 IO 线程 |
| ComposeMainActivity / Compose 页面 | 导航、生命周期、操作反馈、输入和结果展示 |

这是当前结构的说明，不代表全应用已完成 Repository / ViewModel 迁移。其他页面仍有直接 Store 读取，继续拆分时应以具体耗时和重复读取为依据。

## 写入与异步操作

- 专注开始及恢复在同一 Store 锁内完成检查与写入。補记在事务内重新检查任务是否已结算，避免使用界面旧状态覆盖后台结算结果。
- 文件读写、备份校验与恢复通过 lifecycleScope 和 Dispatchers.IO 执行；结果回到界面线程。界面同时只允许一次文件数据操作，防止重复确认，导航不等待文件工作完成。
- 恢复之前停止相关服务；恢复完成或失败后按当前数据重新同步。恢复沿用已有完整快照、暂停监测和计时规则。Activity 销毁后不再发布旧界面结果。
- CSV 预览检测既有课程与同批新课程的周次、星期、节次交集，先出现的课程优先；提交前重新读取当前课表并重验。500 条上限与既有备份校验一致。
- 统计异步生成，新刷新取消旧界面计算；在新报告完成前保留上次报告并标注更新中，失败提供重试。

## 报告口径

- 专注及到场时间分别计算区间并集，裁切到选定统计周期，不混用单位。
- 有效专注段按连续的计时区间计数，相邻服务记录合并。暂停、休息后的不连续区间另计；这并非完整番茄会话次数。
- 到期任务完成率只包含已核验的叶任务周期；请假、待核验及父目标不进入分母，待核验单列。报告不写回任务状态，也不更改限制规则。
- 目标和地点分布使用稳定 ID 标识，重名项不会因名称相同共享动画身份。

## 验证与已知限制

纯逻辑由 StatisticsReportTest 和 TimetableCsvTest 覆盖。OptimizationDeviceTest 在独立 `.qa` 模拟器包中检查异步操作、并发计时及报告 UI；测试会重置 QA 数据，不能在日常使用的数据上运行。

课表学期仍固定为 2026-08-31 起 18 周。普通应用不能阻止系统强停或撤销权限；备用拦截、实地定位和长期后台表现须真机测试。编译、单元测试或模拟器成功不能替代这些证据。
