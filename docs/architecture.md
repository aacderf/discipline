# 架构与数据操作

0.11.7 在既有 Compose / Java 结构上逐步拆分，保留原业务规则和数据库版本。不要为新增界面另建计时、额度或课程状态源。

## 当前边界

| 模块 | 职责 |
| --- | --- |
| Store | SQLite 数据、备份校验与恢复事务；原有数据库与备份版本 4 |
| Engine / Rules | 任务周期、实际计时、定位有效窗口与限制判定 |
| Scheduler / Reminders / AndroidCompat | 提醒调度、权限撤销回退与系统服务适配 |
| StatisticsRepository | 在 Store 锁内一次读取报告所需记录，转换为不可变输入快照 |
| StatisticsReport | 无界面、数据库与服务依赖的纯报告计算；单元测试可直接覆盖 |
| UsageTimeline / AppUsageLimits | 按日期裁切前台事件、共享系统汇总缓存；切换应用仍使用新样本 |
| UsageInsightsRepository | 在 IO 线程按需整理近七天本机应用报告，区分缺失日期；不创建周期采集任务 |
| DeepSeekUsageClient / DeepSeekKeyStore | 固定官方 HTTPS 接口、有限响应读取及推荐格式校验；Key 使用 Keystore 加密且不进入 Store |
| UsageWeekPlans | 用户审核后的定期限额、周边界调度与有效规则合并；不覆盖长期配置 |
| TimetableCsv | 无存储依赖的 CSV 解析、周次校验及导入冲突判定 |
| BoundaryEditing / ReminderWindow | 草稿边界点删除校验、提醒触发窗口的纯逻辑 |
| Timetable | 将解析结果映射到现有课表状态，维护既有周次和编辑规则 |
| DocumentTransfers | 有界文件读取及 UTF-8 写入，调用方必须放到 IO 线程 |
| ComposeMainActivity / Compose 页面 | 导航、生命周期、操作反馈、输入和结果展示 |

这是当前结构的说明，不代表全应用已完成 Repository / ViewModel 迁移。其他页面仍有直接 Store 读取，继续拆分时应以具体耗时和重复读取为依据。

## 写入与异步操作

- 专注开始及恢复在同一 Store 锁内完成检查与写入。補记在事务内重新检查任务是否已结算，避免使用界面旧状态覆盖后台结算结果。
- 关联任务的选择列表与开始检查复用 Engine.canFocus；会话上下文与下一次的选择独立。地点条件只限制专注阶段，不限制已暂停休息的恢复。
- 文件读写、备份校验与恢复通过 lifecycleScope 和 Dispatchers.IO 执行；结果回到界面线程。界面同时只允许一次文件数据操作，防止重复确认，导航不等待文件工作完成。
- 恢复之前停止相关服务；恢复完成或失败后按当前数据重新同步。恢复沿用已有完整快照、暂停监测和计时规则。Activity 销毁后不再发布旧界面结果。
- CSV 预览检测既有课程与同批新课程的周次、星期、节次交集，先出现的课程优先；提交前重新读取当前课表并重验。500 条上限与既有备份校验一致。
- 手动课程编辑也复用周次解析，按最新课表状态保存或删除，保留同步新增的已提醒记录；时间冲突在写入前拒绝。地点边界修改先保留草稿，支持撤销；整项删除仍检查关联，不删除共享历史到场记录。
- 课程导入和确认也在同一 Store 锁内读取最新状态并保存。地图撤销是最多一份、64 个边界点以内的 Bundle 草稿，随 Activity 状态恢复，不进入业务数据库或备份。
- 提前 0 分钟的提醒允许到点后五分钟内补发，以容忍调度延迟；已完成、请假和过期事件不补发。通知成功后才标记已发送，发送与标记受 Store 锁保护。正数提前提醒仍只在执行开始／截止前发送。
- 通知全局或相应渠道禁用时，忽略该提醒的下次重试；任务结算和计时仍正常调度。导入缺少 manual 的旧任务时按零进度读取，显式非法或负进度则拒绝，不改变备份版本。
- 统计异步生成，新刷新取消旧界面计算；在新报告完成前保留上次报告并标注更新中，失败提供重试。
- 默认至少 24 小时的地点任务按已记录进度结算，定位缺口不算完成；较短任务缺口仍待核验。未完成限制开始时间为约定时间与实际结算时间的较晚者，避免延迟结算生成已经过期的限制；原有惩罚 ID 保持幂等，已结算历史不重排。待核验确认在锁内重读任务，拒绝覆盖已完成状态。
- tick 同样处理符合记录结算政策的旧长地点 review 状态；显式 review 政策与短任务继续核验，done／failed 和已有惩罚保持不变。
- AI 使用建议先检查所选应用、整数限额及完整响应，再保存草稿；确认时重验日期与受保护应用。限额仅在该周生效，与长期规则合并取较严格的正值，停用或周期切换使缓存失效或按日期重读。备份版本仍为 4，增加可校验的 state 项而非数据库表。
- 系统汇总不精确等同于屏幕使用记录，系统保留范围、统计周期及多窗口会影响口径。缺失日期显示未知并向 AI 传 null，不推断为零；仅所选应用名称、每日分钟、周期和用户目标发送至官方服务，包名仅留在本机做推荐映射。
- 历史日期采用系统日汇总，只用近当日事件补充今日进度；关机事件结束前台段，启动事件丢弃没有已知终点的旧前台段，避免跨关机、缺失结束事件造成虚增。重启口径依据 [Android UsageEvents](https://developer.android.com/reference/android/app/usage/UsageEvents.Event#DEVICE_STARTUP)。

## 报告口径

- 专注及到场时间分别计算区间并集，裁切到选定统计周期，不混用单位。
- 有效专注段按连续的计时区间计数，相邻服务记录合并。暂停、休息后的不连续区间另计；这并非完整番茄会话次数。
- 到期任务完成率只包含已核验的叶任务周期；请假、待核验及父目标不进入分母，待核验单列。报告不写回任务状态，也不更改限制规则。
- 目标和地点分布使用稳定 ID 标识，重名项不会因名称相同共享动画身份。

## 验证与已知限制

纯逻辑由 StatisticsReportTest 和 TimetableCsvTest 覆盖。OptimizationDeviceTest 在独立 `.qa` 模拟器包中检查异步操作、并发计时及报告 UI；测试会重置 QA 数据，不能在日常使用的数据上运行。

课表学期仍固定为 2026-08-31 起 18 周。普通应用不能阻止系统强停或撤销权限；备用拦截、实地定位和长期后台表现须真机测试。编译、单元测试或模拟器成功不能替代这些证据。
