# 0.12.3：切页与点击卡顿修复

版本 0.12.3 / versionCode 48，2026-10-14。

本轮修复 0.12.2 新增 UI 的性能热点，没有改变任务结算、计时状态、定位、应用限制、数据库或备份格式。

## 原因与修改

1. APK 中 17,772,300 字节的 Noto Sans SC 字体使用 DEFLATE 压缩。字体第一次加载需要在主线程解压至内存。`androidResources.noCompress` 保留完整字体为未压缩资源，允许系统直接映射读取，不用临时系统字体替换正文。
2. 加号矩形原来作为静态 CompositionLocal 的值发布，布局位置变化会使整个提供范围失效。现在发布稳定的 State 对象，卡片用 derivedStateOf 只订阅实际重叠布尔值，同时保留初始布局和滚动时的箭头避让。
3. 公共按钮原来将动画值作为 Float / Dp 返回，在组合阶段读取。改为返回 State，由 graphicsLayer 读取尺度与阴影；标题按压和图标按钮底色、滚动顶栏颜色在绘制阶段读取。文字错峰与关闭动画终态不变，标题不再额外逐帧调整容器宽高。
4. 悬浮面板的无障碍可见性只在实际变化时设置，保留收起时隐藏子树和原有状态描述。

## 验证

- 同一个按压回归测试先运行于已安装的 0.12.2，再运行于 0.12.3。0.12.2 在按压状态改变后的 160ms 中，组合计数由 2 增至 8；0.12.3 的按下与松开动画期间均没有额外内容重组，单次点击仍只执行一次。
- API 36 x86_64 / SwiftShader，960×1800、density 480（320dp），两版本使用相同模拟器与未清除的正式版数据。采样方法跟踪显示字体 Font.Builder.createBuffer 的主线程累计 CPU 耗时约 68.69ms → 3.05ms。采样是热点分析，不等同于真实设备触摸响应时间。
- 各运行一轮相同的 24 次底部导航点击、间隔 0.5 秒的 gfxinfo 测量：0.12.2 为 737 帧、P50 23ms、P95 40ms、P99 85ms，现代 deadline 掉帧 19（2.58%）；0.12.3 为 773 帧、P50 23ms、P95 38ms、P99 53ms，掉帧 21（2.72%）。长尾帧耗时下降，整体掉帧比例没有明显改善，不声称已证明真机全 App 帧率提升。
- 新版刚覆盖安装后的第一次启动记录为 2080ms，旧版已使用的进程冷启动记录为 851ms；ART 与缓存条件不同，未将这两个值作为启动性能改善依据。
- 5 项定向设备检查通过：按压不逐帧重组、字体数字宽度、任务边界与图标薄荷反馈、返回取消与滚动恢复、深色页面不露白底。未反复运行全部业务测试。
- Debug / AndroidTest / Release 构建通过，lint 0 errors、59 warnings。原有 testTag、显式语义及业务源文件对比通过。
- 同一证书签名；已在专用模拟器 `install -r` 覆盖正式版，未卸载或清空正式版数据。字体改为未压缩后 APK 约 99.5MB，较 0.12.2 增约 6.5MB。

没有连接 iQOO／小米真机，本轮不能替代用户设备的体感与长期运行验收。
